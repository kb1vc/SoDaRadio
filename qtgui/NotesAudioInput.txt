AudioInfo is a QIODevice that
implements start/stop/read/write
it owns a format definition
it signals "update"

Its constructor
 takes a sample QAudioFormat format and 
remembers it.

its start method opens the qio device as write only
its stop device calls close on its QIODevice self.

then there is read data and write data.
read data returns 0
writedata accepts the buffer, and eats the samples.
   after the buffer has been consumed, write emits "update"
   and returns the number of bytes taken from the input buffer

So here's what we do.

AudioTXInput is a QIODevice that has all the methods of the AudioInfo object in
the example. 

whenever the example created a new AudioInfo object we don't do anything -- we've
not changed the format and that's all the AudioInfo constructor does.

When a new device is chosen we stop ourselves. we stop our current audio input device
we disconnect from our audio input device

and we call initializeAudio that mimics the example's initializeAudio

----


AudioTXServer owns a socket.
  on creation it creates the audio_tx_socket by waiting for the Radio to create it.
  it connects the readyRead signal from the socket to the processReturn slot
  in the AudioTXServer thingie -- processReturn does nothing. 

on IODevice::write: 

   It eats the data and puts it in an outbount message on audio_tx_socket
   and then returns. Use the "put" object in RadioListener as a pattern.
